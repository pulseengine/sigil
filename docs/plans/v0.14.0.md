# sigil: next-release plan (v0.13.0 cut, v0.14.0 bets)

Status: **draft, work in progress.** Nothing here is shipped or claimed as
done. Written 2026-11-20 against main 30d5521 and the North Star
(`data/north-star.toml` in pulseengine.eu, updated 2026-11-18). A Fable planner
drafted it in a fresh context. A second Fable agent then checked it cold
against the North Star alone, and the plan below is revised from that check.
The rivet items are drafts (`release: v0.14.0`). Each item names its objective
in its description until rivet's `serves:` field ships.

The North Star asks for "signed code running on a microcontroller, with
evidence an assessor can re-check". sigil is the "signed code" part.

## The objective each item moves, stated honestly

The checker refuted most first-draft indicator claims. This table records the
result instead of the wishful version.

| Item | North Star objective | Does it move a *defined* indicator? |
|---|---|---|
| v0.13.0 cut | O2 2026-Q4 committed target | Yes. It is the sigil half of the only committed target: "sigil publishes a release, so the attestation tool can be installed instead of built from git." |
| B1 format v2 | O1 (precondition) | No. It is a precondition for B2 and B4. |
| B2 on-target verifier | O1 | No. O1's indicator is jess's ladder and synth's numbers. The fallback ("builds for target") backs a public claim, so it counts toward O3. |

| B4 offline attestation verify | O2 | Only through a consumer: O2 counts consumer releases whose bundle passes the verify command. |

No item claims a "counts double" bonus. The North Star has no notion of one.

## v0.13.0: cut it narrow, as the Q4 O2 deliverable

Scope:
- REQ-33, REQ-34, REQ-36 (implemented soundness fixes);
- REQ-39 (#395, verify-chain binds the attested content hash; security fix
  in progress);
- REQ-29's merged part (refreshed trusted root, named errors);
- REQ-37 (musl builds), kept here because "installed instead of built from
  git" needs a binary that runs on a fresh machine;
- REQ-35 (VEX), if it lands before the cut.

**Acceptance (can fail):** a CI job on a clean container installs `wsc` from
the release assets (not from git), checks the cosign signature and the SLSA
attestation, and runs `wsc verify` on a signed component and `wsc verify-chain`
on an attested one. Planted bad inputs must exit non-zero: a tampered module,
a module changed after attestation, a wrong key. Which sigil release wohl's Q4
bundle uses is recorded in the release notes.

**Kill:** the release cannot be installed and run on the clean container
without building from source.

## B1. Signature format v2: bind the preamble and the resource bounds

- **Deliverable:**
  - `SIGNATURE_VERSION` 2 (today 0x01, `src/verify-core/src/lib.rs:51`; the
    parser rejects any other version, `sig_sections.rs:215`) hashes the 8-byte
    preamble (#303) and carries a signed resource-limits manifest (#187
    ask 2).
  - A conformance vector set (good and planted-bad signed components) shipped
    as a release asset; B2, B4 and B5 reuse it.
- **Acceptance (can fail):**
  - `poc_verify_accepts_rewritten_module_preamble` loses its `#[ignore]`
    (`src/verify-core/src/signature/simple.rs:852`) and passes.
  - The varve-reported case (component preamble rewritten to a core-module
    preamble) is rejected.
  - Changing a signed bound must fail verification.
  - A test checks the bound is read from the signed field, so it is enforced,
    not just covered by the signature.
- **O2 guard:** v2 invalidates v1 signatures. Before v1 is rejected by default,
  each known consumer re-signs and its verify passes. The v1 policy is an
  owner decision (factory-notice, morning window).
- **Kill:** kiln will not read bounds from a signed field. Then ship the
  preamble binding only.
- **Depends on:**
  - kiln: manifest schema (kiln#415).
  - scry: the bound values.
  - synth: whether the ELF path needs the same manifest (unverified; spike).
- **Closes:** #303 and REQ-32; part of #187.

## B2. A `no_std` verifier on a Cortex-M board

- **Deliverable:** `wsc-verify-core` builds `no_std + alloc` for
  `thumbv7em-none-eabi` and verifies a v2-signed component on real hardware.
  Today 12 files in verify-core use `std`. `src/verify-core/Cargo.toml:12`
  declares the `no-std` category, a public claim nothing backs. wsc-dsse is
  already `#![no_std]` (`src/dsse/src/lib.rs:32`).
- **Acceptance (can fail):**
  - A required CI job builds for `thumbv7em-none-eabi`. This fixes the
    unbacked category claim (O3 territory) even if the hardware step slips.
  - On hardware, the verifier accepts the good vectors from B1 and rejects the
    planted ones: flipped byte, wrong key.
  - A skipped hardware run is a failure (the O1 guard). An emulator run is not
    reported as on-target.
- **Kill:** verify time or RAM exceeds kiln's stated budget, or no board
  runner exists. Then the bet is "builds for target", reported under O3, not
  O1.
- **Spike first:** does a board runner exist?
- **Depends on:** kiln (admit-before-load call site), gale and gust (board and
  runner), B1.
- **Closes:** #187 asks 1 and 3.

## B3. Merkle inclusion proofs in both keyless paths, Rekor v1 and v2

- **Deliverable:** inclusion verification wired into the online and air-gapped
  verify paths, including Rekor v2 (Ed25519 log, checkpoint plus inclusion
  proof). Today both skip it: `src/lib/src/airgapped/verifier.rs:208` and
  `src/lib/src/signature/keyless/signer.rs:674`.
- **Acceptance (can fail):**
  - Fresh production entries from both logs verify.
  - Planted controls must fail: tampered proof, missing proof, wrong
    checkpoint, wrong signer identity, wrong artifact digest.
- **Kill:** v2 tiled-log semantics cannot be verified without live log access.
  Then document SET-only for v2 and keep v1 inclusion.
- **Closes:** #137 and the rest of #259/REQ-29; informs #138.

## B4. The sigil attestation piece of the O2 bundle, verifiable offline

- **Deliverable:** `SigstoreBundle::verify(&trust_bundle, digest)` (#231,
  REQ-28) and one documented offline command that verifies the sigil
  attestation in a consumer's release bundle.
- **Acceptance (can fail):** on a network-less runner with the musl binary,
  verify a consumer release's attestation. The O2 guard applies: remove each
  evidence piece in turn (bundle, inclusion proof, signature, the attested
  artifact) and the command must fail.
- **Indicator:** O2 moves only when a consumer release (wohl in Q4, relay in
  Q1) passes. sigil's own release does not count.
- **Kill:** consumers' bundle format cannot carry what offline verification
  needs. Then the command stays online-only and the bet is dropped.
- **Depends on:** wohl (Q4 bundle), relay (Q1), varve (cosign-bundle path,
  #268 item 2), B3.

## B5. sigil's fork guard as a signed WASI component under kiln

- **Deliverable:** the guard is consumed as a released, wsc-signed component
  pinned by key, verified before each run, and executed under kiln with
  wasmtime as the differential. Today it is built and run unsigned under
  wasmtime (`.github/workflows/claim-check.yml:56-62`).
- **Acceptance (can fail):**
  - `wsc verify` runs before the guard executes.
  - Planted controls must turn the job red: a byte flipped in the guard, a
    wrong key, the verify step removed.
  - kiln, wasmtime and `check.py` outputs must be byte-equal on the guard's
    corpus: 21 decision-table cases, 29 shapes and the live tree, reject cases
    included.
  - No `*_GAP` switch (O5 guard).
- **Kill:** kiln cannot run a wasip2 component with directory preopens. Then
  the gate stays wasmtime-only and is not counted.
- **Spike first:** kiln wasip2 plus preopens.
- **Depends on:** kiln; plant (the guard is due to move to the shared
  `plant guard`, which would make this plant's artifact, signed by sigil);
  varve.

## varve's ingestion rung (not a bet this release)

varve offered to verify wsc's embedded signature when it ingests a component
into a layer. The checker found that as a separate bet it either duplicates
B1's vectors or is undone by varve's existing cosign `SHA256SUMS` check. It
becomes a seam contract once B1 lands. The contract covers exit codes, the
verdict format, the v2 format and key distribution. It also names the threat
cosign misses: the signer identity bound inside the component, which survives
extraction from a layer or re-hosting. REQ-38 stays the umbrella.

## Order

Each step comes from this plan, not from approval of individual steps:
1. #395 security fix, then the v0.13.0 cut.
2. Spikes: board runner, kiln preopens, synth ELF path.
3. B3 and B1 in parallel.
4. B4 and B5.
5. B2 on hardware.

Two L-sized and three M-sized cross-repo bets do not fit one release. The
spikes decide what stays in v0.14.0.
